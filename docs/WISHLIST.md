# Threat Atlas / AtlasSOC product wishlist\n\nRequested by Robert, 14 November 2026. This is the product wishlist for the Threat Atlas\nscreensaver and AtlasSOC Desktop. It is not the status-page widget wishlist.\n\nAll items are **non-commercial only**. A source is in scope only when its terms allow this\nproject's non-commercial use; a free tier that requires a commercial licence for this use is\nout of scope. Provider attribution, licence text and rate limits are acceptance criteria, not\nimplementation details.\n\n## Cross-cutting requirements\n\nEvery OSINT source must satisfy these before it ships:\n\n- **Licence and attribution.** Record the source, licence name, attribution text and link in a\n  central registry and show it in the UI (source detail and an "OSINT sources" panel). Do not\n  ship a source whose terms are unclear or commercial-only.\n- **One worker per source.** Network work runs off the render thread, bounded in memory and\n  scope, with a single in-flight request per source.\n- **Rate limiting.** Each source has a declared minimum interval and cache TTL. The worker\n  honours `Retry-After`, backs off exponentially on errors and never retries a 4xx in a loop.\n  The minimum interval is enforced across restarts where the API provides a persisted cooldown\n  (the Radar worker already does this).\n- **Conditional requests.** Use `ETag`/`If-None-Match` or `If-Modified-Since` where the source\n  provides it. A 304 is a success and extends the cache without parsing.\n- **No bundled secrets.** Optional API keys are supplied by the user and stored in the OS\n  credential store (Windows Credential Manager, macOS Keychain). Never write keys to settings,\n  logs, packages or the repository.\n- **No probing or fetching of malicious content.** URL/domain sources are displayed and linked;\n  the app must not fetch a malware or phishing URL to "enrich" it.\n- **Normalised event model.** `timestamp`, `source`, `category`, `ip`/`prefix`, `asn`, `country`,\n  `confidence`, `title`, `url`, `first_seen`/`last_seen`. Unknown fields are ignored safely.\n- **Source toggles and filters.** The user can enable/disable each layer or panel; the UI shows\n  which source produced an item and never presents community reports as confirmed attacks.\n- **Tests.** Parser fixtures, rate-limit/cooldown tests, licence-registry coverage and failure\n  cases. Unit tests use fixtures and never the live network. Live smoke tests are manual and\n  documented separately.\n- **Documentation stays English.** Update `docs/ATLAS-SOC-BETA.md` and the source registry when a\n  source ships. No release is implied by an implemented wishlist item.\n\n## Work packages and handover\n\nThe items are deliberately **unassigned**. As of 14 November 2026, **CL owns distribution** of\nthe remaining work; CL assigns an item to an authorised agent and records the owner and exact\nbranch in the private handover (`project-status-dashboard/handovers/mac.json`) before work\nstarts. ## ATLAS-SOURCE-INFO-001 — (i) link to each data source's front page

Requested by the owner on 16 November 2026 for the next version of all projects; "if we do not already have it in Settings". **Checked on 16 November 2026:** AtlasSOC 0.8.0-rc.1 has no per-source link in Settings. It has only the key guide, the AI help prompt, the Cloudflare token guide and the support links.

**What to build**

- One **(i)** symbol next to every data source in Settings (and in the source list the user can open from the main view where one exists). Clicking it opens that provider's own front page in the default browser. One link per source, nothing else, no pop-up essay.
- Sources to cover: Cloudflare Radar, GreyNoise, CISA KEV, FIRST EPSS, Tor exit list, SANS ISC / DShield, Team Cymru, abuse.ch (SSLBL, ThreatFox, URLhaus), AlienVault OTX, ransomware.live, Shodan InternetDB, AbuseIPDB, SSLMate Cert Spotter, Spamhaus DROP and Phishing.Database. Sources a given app does not use get no symbol.
- Use a **drawn icon** (a circle with an "i", themed for dark and light) instead of an emoji. Emoji depend on installed fonts and the software renderer on Windows and Linux. Where an app has no icon support, use the text glyph "ⓘ" or the word "Info". The control needs a text label for screen readers ("About GreyNoise, opens greynoise.io") and must work with the keyboard.
- The links live in **one table in the code** (source id, display name, https front-page URL) and are also listed in `docs/OSINT-SOURCES.md`. No tracking parameters and no redirects through our own server. Nothing is fetched until the user clicks; the click opens the browser and the app sends nothing.
- Existing attribution and licence text for each source stays as it is. The (i) link is in addition to it, not a replacement.

**Acceptance**

- Every source shown in Settings has exactly one (i) link, https only, to the provider's own domain; a unit test checks the table (one entry per source, https, no query string).
- A release check opens every link and records HTTP 200 (or the provider's normal redirect to its own site) in the release evidence; a link that fails is fixed before the release.
- The symbol is present and works in the screensaver (where its settings allow links), AtlasSOC on Windows, macOS and Linux. The Settings layout tests still pass at 1920x1080 at 125 % scaling.
- Not part of RC1 and not urgent.

## ATLAS-SAVER-MAP-001 — compass and hourly time zones on the screensaver map

Requested by the owner on 18 November 2026 for the **next screensaver version** (0.5.0), so it has something new to show. Not part of the current builds.

**What to build**

- **Compass:** the only compass today is the needle-less compass rose in the screensaver's Seeker theme (`seeker_overlay` in `crates/core/src/render.rs`). AtlasSOC and the standard screensaver view have none (checked by the owner in AtlasSOC 0.8.0-rc.1 on 20 November 2026). Make that compass rose a shared map element and show it in the standard screensaver view; do not write a second compass.
- **Time zones:** mark the world's time zones on the map, each labelled with its actual local hour as a whole number on the 24-hour clock, 0, 1, 2 … 23, relative to UTC.
- **Update rhythm:** the hour labels change only on each full hour. No ticking clock on the map.
- Layout, placement and colours are MAC's call (design owner). The labels must not cover the arcs, counters or attribution text, and must stay readable on dark and light themes.

**Acceptance**

- A unit test checks the hour for every zone against UTC at a fixed instant, including half-hour zones if they are shown.
- A test with a clock just before and just after a full hour shows that the labels change once, on the hour, and not in between.
- Visual check of the screensaver at 1920x1080 and 2560x1440 on Windows and macOS: compass and labels visible, nothing overlapping.
- The screensaver's frame budget stays within its current limits.

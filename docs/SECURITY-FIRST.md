# Screensaver and security priority

Robert's instruction, 2 November 2026: security is the highest priority. Fix/triage vulnerabilities first, then bugs in the public Atlas screensaver, before beginning standalone implementation. Standalone and SOC wall work remains planned and blocked behind screensaver acceptance. The Mac Radar branch remains an isolated alpha, not a public screensaver fix or release.

Every local/CI build must run `python3 scripts/security-sanity.py` using reviewed cargo-audit 0.22.2 and a fresh RustSec database. Findings, audit warnings, missing tool, network/database failure or invalid results block builds. Record evidence JSON for the exact source/lockfile, including dependency advisories and links. Scan all locked dependency trees before target-specific reachability triage; do not suppress findings because a different OS was built. No silent ignore list or stale/offline clean result.

Also review dependency currency (including available major versions), yanked/unmaintained crates, pinned GitHub Actions and native toolchain/SDK dependencies for each build/RC. An outdated version is not by itself a confirmed vulnerability; it is a maintenance finding requiring update/testing or an explicit, expiring compatibility/security review before release. Do not blindly bump packages or claim a clean advisory scan proves every package is current. Dependabot weekly update PRs complement, but do not replace, the per-build check. Current GitHub alert API access is unavailable/disabled and is not evidence of zero alerts.

Code sanity includes source/secret scan, untrusted-input bounds and malformed-data tests, TLS verification, token storage/log redaction, redirect behavior, updater signature enforcement, native static checks and applicable regression tests. Security findings block release until resolved and independently checked. Never disable OS protections to make a build pass.

Report public dependency advisories in [Known Vulnerabilities](KNOWN-VULNERABILITIES.md), sorted by verified numeric CVSS score descending. Unscored entries follow scored ones. Include advisory ID/source, score/vector/version, affected dependency/version/build, status, fix/mitigation and last verification. Publicly known advisories may be linked. Suspected unpublished application vulnerabilities go through SECURITY.md's private disclosure process; expose only redacted status on the LAN dashboard until coordinated disclosure.

Dashboard feature/wishlist/bug statuses are item-specific: planned, implemented, locally verified, awaiting independent verification, blocked, or fixed in a named release. A request sent to Billy is not receipt or implementation. Keep historical approvals and release limitations intact. MAC owns status/mac.json; Billy owns status/billy.json. Update only changed content, poll via the existing single ten-minute cached reader, and never merge the status-only branch into code.

# Atlas status dashboard sections

`sections.html` adds individual feature, wishlist, bug, dependency-currency and Known Vulnerabilities sections to the existing LAN monitor. Data comes from the monitor's cached `/api/project-status` response (MAC-owned `status/mac.json` on the status-only branch). One backend reader polls Git every ten minutes; browser refreshes use cached local data. Keep existing host/subnet restrictions and Mac-local command mutation policy.

Known Vulnerabilities are sorted by numeric CVSS base score descending, unknown scores last. Display the source vector, affected component, individual resolution status and advisory links. Empty/unavailable evidence is not a clean result. CVSS is owned by FIRST and used by permission; see https://www.first.org/cvss/v3.1/specification-document . Security score describes advisory severity, not proven local exploitability.

Never merge the status branch into application code. The service preserves its SQLite database and runs as a per-user LaunchAgent from Application Support; a running dashboard is not agent health. Hosting remains restricted to the previously authorized LAN and loopback. Historical reported evidence stays separate from independently verified checks.

## Runtime and Google login

`runtime/` contains the updated monitor server and pages; use alongside the established `releases.py` implementation. Its SQLite database, caches, Google owner binding and real login config are local only. `/agents` holds detailed health; `/` retains a summary and manual MAC task form. Tests run in an isolated temporary database and stub upstream fetchers.

Google Identity Services login is **not active** until configured. Create a Web OAuth client with origins `http://localhost` and `http://localhost:8765` for testing. No redirect URI/client secret is needed for the ID-token callback flow. Register a genuine HTTPS origin for LAN usage; `.local` plain HTTP is unsuitable. Copy `google-login.example.json` to `google-login.json` only outside Git and enable after supplying the real client ID. Owner is ibert@ibert.se; verify email, Workspace authority and stable subject, not an alias. Use the maintained official `google-auth` verifier with its requests transport; never decode-only JWTs. Signature/issuer/audience/expiry verification comes from that library; nonce, owner allowlist and one-time challenge are separately checked. Session cookies are HttpOnly/SameSite with Secure on HTTPS, expire after one hour, and are invalidated by service restart. Bad/missing Google configuration must not be bypassed. `/auth/logout` clears the server session; login attempts are limited. Missing client/library or uncompleted Google verification is not a working sign-in claim. Follow https://developers.google.com/identity/gsi/web/guides/verify-google-id-token .
